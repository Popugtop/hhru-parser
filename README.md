# Парсер вакансий hh.ru (Тюмень, без опыта)

Сбор данных для учебного исследования «Возможности для занятости выпускников
с высшим образованием» (ПИР, ТюмГУ). Проект прошёл несколько поколений
дизайна — актуальное описано ниже первым, остальные — в конце (раздел
«Предыдущие версии»), они не удалены и продолжают работать.

**Актуальная версия — `hh_parser.cli_v3_api`**: официальный API
`api.hh.ru/vacancies` (нужен Bearer-токен приложения), сплошной сбор всех
вакансий белого списка (84 стартовых профроли, 6 сфер) + подобранная
подвыборка с тем же составом по сферам, что и в предыдущей (website) версии,
+ самопроверка части А против неё же.

## Установка

Нужен Python 3.11+ (проверено на 3.14).

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### Токен для официального API

В `.env` (в `.gitignore`, не коммитить, значения никогда не печатать в
консоль/логи):

```
HH_ACCESS_TOKEN=<bearer-токен приложения>
HH_USER_AGENT=<Название приложения/версия (контактный email)>
```

Повторно запрашивать токен не нужно — повторный запрос отзывает предыдущий.

## Тесты

Все парсеры (SSR-JSON и официальный API, коды hh.ru, сектор работодателя,
текстовые правила, выборка, матчинг подвыборки, экспорт) покрыты тестами на
фикстурах — реальных сохранённых ответах hh.ru. Прогнать перед любым реальным
сбором:

```bash
.venv/bin/python -m pytest tests/ -q
```

## Сбор через официальный API (`cli_v3_api`, актуальная версия)

```bash
.venv/bin/python -m hh_parser.cli_v3_api
```

Делает по порядку:

1. Загружает справочник профролей и белый список (тот же, что в
   `output/v2_matched/roles_whitelist.csv`).
2. Часть А (количества по сферам) — **в двух вариантах**: с фильтром
   зарплаты и без.
3. **Самопроверка**: часть А (API, с фильтром зарплаты) сравнивается со
   старой website-версией (`output/v2_matched/counts_by_sphere_v2_*.csv`).
   Если расхождение по какой-то сфере больше допуска (по умолчанию ±10%) —
   печатает таблицу расхождений и **останавливается, не начиная часть Б**
   (чтобы не потратить лимит запросов на заведомо кривую выборку). Если
   расхождение проверено вручную и объяснимо (обычная ротация объявлений за
   несколько дней между сборами) — повторить запуск с `--skip-self-check`.
4. Часть Б — сплошной сбор **всех** вакансий белого списка (без лимита на
   работодателя), затем отдельно вычисляет (seed=42) подобранную подвыборку
   с тем же составом по сферам, что и «ВО требуется» (та же методика, что в
   `cli_v2`: максимум 3 вакансии на работодателя) — и помечает её колонкой
   «В подвыборке с одинаковым составом сфер», а не выгружает отдельным
   файлом.

### Флаги

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--area` | 95 | Код региона hh.ru (95 — Тюмень) |
| `--search-period` | 30 | Период поиска, дней (параметр API — `period`) |
| `--seed` | 42 | Seed подбора матчинг-подвыборки (воспроизводимость) |
| `--pause-min` / `--pause-max` | 0.5 / 1.0 | Пауза между запросами к API, сек |
| `--cache-dir` | `cache` | Кэш сырых JSON (`cache/api_search/`, `cache/api_vacancy/`) |
| `--output-dir` | `output/v3_api_<дата>` | Куда сохранять результат |
| `--env-file` | `.env` | Где искать токен/UA |
| `--self-check-tolerance` | 0.10 | Допуск часть А (API) vs сайт v2, доля (0.10 = ±10%) |
| `--skip-self-check` | выключен | Пропустить самопроверку и продолжить часть Б, даже если расхождение больше порога |

На 429 — ждёт (`Retry-After` или возрастающий backoff) и повторяет; на 401/403
— немедленно останавливается (неверный/просроченный токен), уже собранное
сохранено.

Кэш: `cache/api_vacancy/<id>.json` (детали вакансии) хранится без даты в
ключе и переживает любой перезапуск — деталь вакансии от запуска к запуску
не меняется, а это самая дорогая часть сбора. `cache/api_search/*.json`
(части А и Б — счётчики и страницы поиска), наоборот, кэшируется **с датой
в ключе** — поиск на разные дни не путается друг с другом, каждый день
реально обращается к API (до 2026-10-21 была ошибка: дата в ключ не входила,
и повторный запуск через 12 дней вернул побайтово старые числа без единого
сетевого запроса — исправлено, см. `output/README.md`).

При повторном запуске в тот же день с настройками по умолчанию
`output/v3_api_<дата>/` **перезаписывается** — используйте `--output-dir`,
если нужно сохранить оба результата.

### ⚠ Поиск hh.ru не абсолютно полон

Проверено дважды (см. `output/README.md`): часть активных, неархивных,
прошедших модерацию вакансий иногда не находится через `GET /vacancies` ни
при каких фильтрах (даже при поиске по голому `employer_id`), хотя
`GET /vacancies/{id}` их прекрасно отдаёт. Похоже на реальный пробел в
поисковом индексе hh.ru, а не на ошибку в коде — поэтому счётчики части А и
пул части Б — это нижняя граница истинного числа вакансий, не точная цифра.
Доля таких «невидимых» вакансий в вашей выборке может различаться от прогона
к прогону.

### Примеры

```bash
# Другой город, другой период, без сверки с website-версией
.venv/bin/python -m hh_parser.cli_v3_api --area 2 --search-period 14 --skip-self-check

# Другой seed — другой случайный состав подобранной подвыборки
.venv/bin/python -m hh_parser.cli_v3_api --seed 7

# Не перезаписывать сегодняшний прогон
.venv/bin/python -m hh_parser.cli_v3_api --output-dir output/v3_api_rerun
```

### Результат

`output/v3_api_<дата>/`:
- `vacancies_v3_api_<дата>.xlsx` — главный файл, листы: «Выборка»,
  «Количества по сферам», «Сферы x Группы ВО», «Отсев», «Самопроверка»,
  «Параметры сбора», «Словарь колонок».
- `vacancies_v3_api_<дата>.csv` — тот же лист «Выборка» (`;`, `utf-8-sig`).
- `counts_by_sphere_v3_api_<дата>.csv` / `_no_salary_<дата>.csv` — часть А,
  оба варианта фильтров.
- `roles_whitelist.csv`, `run_info_v3_api.json` — белый список и все
  параметры запуска (включая результат самопроверки и причины отсева).

Подробное описание всех поколений вывода — в `output/README.md`.

## Предыдущие версии (не удалены, работают как раньше)

### v2 — белый список + 2 группы, через сайт (`cli_v2`)

```bash
.venv/bin/python -m hh_parser.cli_v2
```

Тот же белый список/сферы/2-группная схема, что в v3-api, но источник —
HTML-страницы сайта (SSR-JSON), а не официальный API. Нужен, если API
недоступен или для сверки (см. самопроверку выше).

### v1 — три группы образования, целые категории (`cli`)

```bash
.venv/bin/python -m hh_parser.cli --probe                                  # пробный запрос
.venv/bin/python -m hh_parser.cli --quota-higher 5 --quota-not-required 5 --quota-special-secondary 5  # пробный сбор
.venv/bin/python -m hh_parser.cli                                          # полный сбор (квоты 80/80/40)
```

Первая версия: 3 группы образования (Высшее/СПО/Не требуется), широкие
категории профролей целиком (ИТ, Юристы, Финансы, Наука, Медицина, Продажи),
источник — сайт. Основные флаги: `--area`, `--search-period`, `--seed`,
`--pause-min`/`--pause-max` (2.0/4.0 — вежливее, чем у API), `--quota-higher`/
`--quota-not-required`/`--quota-special-secondary`, `--cache-dir`,
`--output-dir`, `--probe`, `--source` (`hh` или `tv`).

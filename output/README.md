# Что лежит в `output/`

Несколько поколений одного и того же сбора — дизайн менялся по ходу работы.
**Самое актуальное и полное — `v3_api_<дата>/`** (раздел 4 ниже). Остальное
оставлено для истории/сверки, не нужно для текущего анализа.

## 1. Корень `output/` — первая версия (`hh_parser.cli`)

`sample_vacancies.{csv,xlsx}`, `counts_by_sphere.{csv,xlsx}`, `run_info.json` —
самый первый прогон: 3 группы образования (Высшее / СПО / Не требуется),
широкие категории профролей целиком (ИТ, Юристы, Финансы, Наука, Медицина,
Продажи), источник — HTML-страницы сайта (SSR-парсинг). `archive/` — более
ранняя копия того же самого.

## 2. `v2_matched/` — вторая версия (`hh_parser.cli_v2`)

Дизайн сузился до **белого списка** из 84 «стартовых» профролей (не целые
категории справочника, а конкретные роли уровня начинающего специалиста),
сгруппированных в 6 сфер: IT, Право, Экономика и финансы, Управление и офис,
Инженеры, Продажи (офисные) — список и логику распределения ролей по сферам
см. `roles_whitelist.csv` и `hh_parser/whitelist.py`.

Образование свели к **2 группам** вместо трёх: «ВО требуется» (education=
higher) и «ВО не требуется» (special_secondary + not_required_or_not_specified
вместе) — так проще сравнивать для гипотез исследования. «ВО требуется» —
сплошной отбор (все подходящие, максимум 3 на работодателя); «ВО не требуется»
— подобрана случайно (seed=42) с **тем же составом по сферам**, что получился
в «ВО требуется» после отбора, — это и есть матчинг для сравнения групп.

Часть А (`counts_by_sphere_v2_*.csv` / `_no_salary_*.csv`) — количества по
тем же 6 сферам + белый список целиком + контекстные категории (Медицина,
Наука) + «Все вакансии», в двух вариантах фильтров (с зарплатой / без).

Источник данных — **HTML-страницы сайта** (SSR-JSON в `HH-Lux-InitialState`),
не официальный API: на момент сбора (2026-10-07) токена для API не было.

## 3. `v3_all_specialists/` — третья версия, веб (не запущена)

Задумывалась как сплошное обследование ВСЕХ вакансий белого списка (без
лимита 3 на работодателя), тем же способом через HTML-страницы сайта. Код
есть (`hh_parser/sample_v3.py`, `cli_v3.py` и т.д.), но этот прогон заменён
версией через официальный API (раздел 4) — папка пуста.

## 4. `v3_api_<дата>/` — актуальная версия, официальный API (`hh_parser.cli_v3_api`)

Тот же белый список и те же 6 сфер, что в `v2_matched/`, но:

- **источник — официальный API `api.hh.ru/vacancies`** (Bearer-токен из
  `.env`), а не HTML-страницы — быстрее и официально разрешено (0.5–1 с между
  запросами вместо 2–4 с);
- **часть А в двух вариантах** фильтров (с зарплатой / без), как и в v2;
- **самопроверка**: часть А через API сравнивается с website-версией
  (`v2_matched/counts_by_sphere_v2_*.csv`), допуск ±10% по каждой сфере —
  результат сравнения записан в run_info и на листе «Самопроверка» xlsx;
- **часть Б — сплошной сбор ВСЕХ вакансий белого списка**, без лимита на
  работодателя (колонка «Номер вакансии работодателя в выборке» — просто
  порядковый номер, не ограничение);
- внутри этой же таблицы колонка **«В подвыборке с одинаковым составом сфер»**
  (да/нет) — та же методика матчинга, что в v2 (все «ВО требуется», максимум
  3 на работодателя, + столько же «ВО не требуется» случайно с тем же
  составом по сферам, seed=42), но вычисленная внутри этого же прогона, а не
  как сверка с внешним файлом v2.

Файлы:
- `vacancies_v3_api_<дата>.xlsx` — главный файл. Листы: «Выборка» (все
  собранные вакансии), «Количества по сферам» (часть А, вариант с зарплатой),
  «Сферы x Группы ВО» (сводная по факту собранного), «Отсев» (причины
  исключения отдельно для сплошного сбора и для подвыборки), «Самопроверка»
  (API vs сайт v2), «Параметры сбора», «Словарь колонок».
- `vacancies_v3_api_<дата>.csv` — те же данные, что на листе «Выборка»
  (`;`, `utf-8-sig`).
- `counts_by_sphere_v3_api_<дата>.csv` / `_no_salary_<дата>.csv` — часть А,
  оба варианта фильтров.
- `roles_whitelist.csv` — тот же белый список ролей, что и в v2.
- `run_info_v3_api.json` — дата/время, все параметры фильтров, seed, размеры
  пулов, результат самопроверки, отсев по причинам.

### ⚠ Известное ограничение: поисковый индекс hh.ru пропускает часть активных вакансий

Проверено дважды (раздел «Самопроверка» ниже): если взять ID вакансий из
website-подвыборки v2, которые сейчас не находятся через API-поиск по тем же
фильтрам, часть из них — это ожидаемо (вакансия ушла в архив или удалена), но
часть — это вакансии, которые по данным `GET /vacancies/{id}` полностью
активны и видны (`archived: false`, `hidden: false`, `approved: true`,
`closed_for_applicants: false`, `type: open`), но не находятся поиском
`GET /vacancies` **ни при каких фильтрах, включая голый `employer_id` без
других условий**. Прямого объяснения в полях API нет — похоже на реальный
пробел в поисковом индексе hh.ru (не в нашем коде: прямой запрос по
единственной профроли против суммы отдельных запросов по каждой профроли
даёт одинаковый результат — значит, параметры запроса передаются и
учитываются корректно).

**Следствие:** счётчики части А (`found`, кластер `education`) и пул части Б
— это нижняя граница реального числа вакансий, не точное число. Доля таких
«невидимых» активных вакансий варьируется от прогона к прогону (0/32 — 2
дня, 7/22 — 12 дней) и не привязана к конкретным сферам.

### Самопроверка — хронология прогонов

**2026-10-09** (первый прогон). Часть А (API) сравнена с сайтом (`v2_matched`,
собран 2026-10-07, на 2 дня раньше). 2 сферы превысили ±10% («Управление и
офис»: 35 vs 43, «Инженеры»: 22 vs 26) — проверено вручную: 0 из 32 вакансий
этих сфер оказались «активны, но не найдены» без объяснения (7 ушли в архив,
1 удалена, HTTP 404). Обычная ротация, прогон продолжен с `--skip-self-check`.

**2026-10-21** (повторный прогон, 12 дней позже). Сначала воспроизвёл
побайтово те же числа, что 09.10, — оказалось, кэш `cache/api_search`
(часть А и пул части Б) не учитывал дату в ключе, поэтому сеть не
трогалась вообще (баг найден и исправлен — см. `hh_parser/api_client.py`,
`_cache_key`/`search`; старый кэш удалён). После исправления и повторного
(настоящего) запроса к API — другие 2 сферы превысили ±10% («Право»: 10 vs
12, «Экономика и финансы»: 20 vs 18). На этот раз проверка вручную нашла
7 из 22 вакансий «активных, но не найденных» без объяснения архивом/удалением
— отсюда и появилась заметка о пробеле в поисковом индексе выше. Прогон
продолжен с `--skip-self-check`, расхождение принято как известное
ограничение источника данных. Агрегаты («Итого специалистские», «Все
вакансии») в обоих прогонах совпали в пределах 5%.
